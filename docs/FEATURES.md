# claude-history-gui — master parity checklist (FEATURES.md)

Revision 2 (review findings resolved; see DESIGN.md §20). Every user-visible feature, behavior, string, key
binding, config option and CLI flag of claude-history v0.1.76 (TUI list mode, viewer, CLI, subcommands, agent
protocol), plus the GUI-only features decided in DESIGN.md. Each row has a stable ID used by DESIGN.md §17.

Columns:
* **Original** — upstream behavior with source (`src/...:line` in `C:/git/opensource/claude-history`, or the
  inventory section when the inventory is the reference: LIST, VIEW, CLI, AGENT, ADD).
* **GUI** — where/how the GUI implements it (file, component or core API; DESIGN § reference). "needs Kn" = depends
  on core gap Kn (DESIGN §4.3).
* **Acceptance** — verification code(s) and the concrete check. Codes (DESIGN §15.1): **U** core unit test, **P** pure
  GUI-crate unit test, **G** gpui test (hermetic harness, `RecordingServices`), **Q** QA scenario (named), **S**
  screenshot review, **M** automated CI/release check, **R** integrator review against DESIGN §15.7 (the concrete item
  is named), **D** deferred manual check by the user (DESIGN §15.9).
* **WP** — the single owning work package (DESIGN §17). The owner implements the acceptance check and makes it pass.
  `WP-C` rows are core behavior: WP-C confirms the named core test exists and passes, or writes it.

Decision tags in the GUI column: **[fix]** TUI quirk fixed, **[keep]** quirk preserved for parity, **[dev]**
deliberate GUI deviation (DESIGN §2), **[add]** additive GUI feature.

Test-only hooks referenced below (`#[cfg(test)]`, owned by the pane's WP): `ListPane::inject_load_event(LoadEvent)`,
`ListPane::last_row_menu()`, `ListPane::row_menu_target(token)`, `ViewerPane::render_ctx()`, `RecordingServices::{calls, clipboard, answer_*}`,
`test_support::{fault, synth, global_lock}`.
